# V4 Rev D 아두이노 코드 점검

2026-10-24 · 비교 기준 `ab8c454` · 검토 대상 `firmware/main/` 전체와 대응 JS·회로·생성기.

## 판정

실제 스케치의 호스트 실행, JS 교차 비교, UNO R3와 R4 WiFi 컴파일을 통과했다. 현재 구조에 맞게 뒤집기를 금지하고5면 풀이, 독립 끝 센서12개, 서보 단계 지령을 적용했다. 이는 실제 큐브의 회전 성공이나 하중 안전을 인증한 결과가 아니다. 실제 보드 업로드·Wokwi 실행·실물 부하 시험은 이번 세션에서 하지 않았다.

## 발견한 문제와 수정

1. **코어 구동 없는 뒤집기:** R/L 외층만 구동하므로 전체 큐브 회전은 보장되지 않았다. 실제/가상 `F`와 저수준 flip을 거부하고, 흰색 U 아래·논리D 고정으로 바꿨다. Cross·OLL/PLL·섞기도 동일한15수 집합을 사용한다. `M F D R`은 첫 F도 실행하지 않는다.
2. **직렬 결합 접점의 오판:** 두 헤드 중 하나만 스위치에서 떨어져도 후퇴로 볼 수 있었다. 결합6개/후퇴6개를 분리하고74HC165 두 개로 읽는다. 해당 쌍의 모든 목표 접점 ON·반대 접점 OFF가 필요하다. 양 끝 동시 ON과 미사용 비트 오류도 거부한다. 실패 후 재시도는 실제 접점을 다시 읽는다.
3. **서보 급격한 끝각 지령:** 180도를 한 번에 지령하던 것을1도/4ms로 바꿨다. 전체720ms이며, JS도 지령 시작점·진행 시간·복귀를 동일하게 추적한다. 정적 힘 제한은 아니다.
4. **느슨한 숫자 해석:** 기존 `Q 2` 또는 인자 없는 `Q`가 실제 모터 모드를 켰다. `T 65536`은16비트 대기 값으로 잘릴 수 있었고 `S 42junk`는42로 해석됐다. 부호·범위 초과·뒤따르는 문자를 거부하는 공통 숫자 검사를 추가했다. `Q`는0/1, `T`는0..60000, `S`는32비트 부호 없는 정수만 허용한다. 잘못된 입력13종과 정상 경계6종을 실제 스케치로 검증했다.
5. **시운전 입력 진단 부재:** `I`에12개 실제 접점과 프레임 상태를 출력하게 했다. 예: `SENS order=FBRLDK en=000000 rt=111111 frame=1`. 캐시된 장착 상태와 독립적이다.

## 핀·전기 인터페이스

STEP은 F=D2/R=D3/B=D4/L=D5/아래D=D6, DIR=D7이다. 서보 신호는 FB=D8/RL=D9/D=D10/LOCK=D11이다. FB/RL은 각 신호에 서보 두 개가 연결된다. 센서는 DATA=D12/CP=D13/PL=A0, 버튼=A2, 부저=A3, LCD=A4/A5이며 A1은 남는다.

74HC165 가까운 칩 D0..D5는 결합 F/B/R/L/D/LOCK, 먼 칩은 같은 순서의 후퇴다. Q7을 상승 클록 전에 읽고16비트를 이동시킨다. 가까운 바이트가 상위8비트다. 입력은 외부10kΩ 풀업과 NO→GND, 미사용 D6/D7은 HIGH다. 사진의74HC595는 출력용이므로 대신 사용할 수 없다. 회로도와 생성 계약을 함께 검사했다.

서보 전원은 별도6V 공급과 공통 GND를 사용한다. Arduino5V에서6개 서보를 공급하지 않는다. A4988 유지 전류·전원 용량·발열은 코드의 동시 회전 수와 별개다. Timer/Servo/tone/I2C의 두 보드 컴파일은 통과했으나 실제 파형과 라이브러리 런타임 호환은 보드 시험이 필요하다.

LiquidCrystal I2C의 AVR 아키텍처 선언 때문에 R4 컴파일에서 호환성 경고가 나온다. 컴파일 성공과 실제 LCD 동작을 구분한다. R3의754B는 스택 최고 사용량을 뺀 실측 여유가 아니며, 실물 기본 보드는 R4 WiFi다. `STAGE_MAX=40`, `SOL_MAX=128`은 현재 표/탐색 한계 내에서 사용하며, 표를 바꾸면 생성기의 최대 길이 검사도 다시 해야 한다.

## 남은 제한과 사용 조건

- `SOLVED ok=1`은 내부 모델의 성공이다. 엔코더·색 인식·스마트큐브 피드백이 없어 탈조·핀 미끄러짐·손으로 바꾼 상태를 자동 감지하지 못한다. `R`도 실제 큐브를 맞추는 명령이 아니다.
- `Q 1`은 이후 소프트웨어 동작을 생략한다. A4988 전원/ENABLE을 차단하거나 이미 지령한 서보를 해제하지 않는다. 비상정지로 사용할 수 없다.
- 동작은 블로킹이다. 모터 회전·서보 이송·탐색 중 새 시리얼/버튼을 즉시 처리하지 않으며, 끝 센서를 회전 중 연속 감시하지 않는다. 물리적 구동 전원 차단 수단이 필요하다.
- 센서는 마지막 상태 확인용이다. `waitSensor`는 서보 지령 이동 뒤 시작한다. 기본720ms 이동+최대1500ms 센서 대기이며, `T 0`은 무한대가 아니라 최대60초 대기다. 끼임 힘을 제한하지 않는다.
- 전원 투입 시 서보는180도를 지령한다. 실제 초기 각도 피드백이 없으므로 최초 시험은 큐브·링크를 분리해 수행한다. 가상 모드 상태를 실물 상태로 간주해 이어서 운전하지 않는다.
- 접점은 핀의 충분한 삽입 깊이나 출력물 파손을 직접 측정하지 않는다. 구매 레버의 작동점·끝각·오버트래블과 스위치 고정 상태를 실물에서 검증해야 한다.
