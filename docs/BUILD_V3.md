초기 검토 중 Ø8 중앙축을 통과시키려고 센터 줄기를 넓혔더니 X/Y축 회전 시 엣지·코너와 충돌했다. 최종본은 **Ø6 고정축 / 센터 관통 Ø6.25 / 원래 유지 트랙 외형**을 사용한다. 이 과정에서 충돌했던 형상은 최종 파일에 포함하지 않았다.

## 회전 방지 원리

```text
큐브 전체의 반력:
코어 D 평면 -> 황동 시임 -> 고정 강재 Ø6 축 -> 양 끝 SHF6
             -> 알루미늄 브리지 -> 합판 박스/금속 앵글

작동 면 회전:
NEMA17 -> (F/B는 40T:40T 벨트) -> 회전축 -> 허브 -> 판 -> 강철핀 -> 엣지/코너

반대 면 고정:
반대 면 소켓 -> 구동핀/구동판 -> 축 -> 금속 인덱스 휠
             -> Ø3 잠금핀 -> 잠금 브래킷 -> 캐리지 -> MGN 블록/레일 -> 프레임
```

중앙축은 모터가 돌리는 축이 아니다. 두 SHF6를 프레임에 고정하여 중앙축이 돌지 않게 한다. 코어는 두 분할 부품과 D 평면 키로 중앙축에 고정되고, 내부 금속 링 2개가 축 방향 이동을 막는다. 나머지 센터는 코어에 대해 회전 가능하다. F/B 센터는 중앙축 둘레를 직접 미끄러져 회전하며 소량의 플라스틱 호환 윤활제를 쓴다. 상용 큐브에 구멍만 뚫어 같은 구조로 쓸 수 있다고 가정하지 않는다.

고정축에는 중앙 36 길이, 깊이1의 평면을 가공한다. 축 중심을 원점으로 평면은 x=+2.00, 코어 포켓 평면은 x=+2.10이다. 이 사이에 0.10 두께 시임을 끼우되 실측 후 0.05~0.15 범위에서 맞춘다. 억지 조임으로 코어를 변형시키지 않는다. 코어를 0.10 N·m(50 mm 레버에 2 N)로 양방향 가압하여 미끄러짐을 먼저 확인한다.

계산 예: 강재 G=79 GPa, Ø6 원형축, 한쪽 280만 반력을 받는 보수적 모델에서 0.10 N·m에 약0.16° 비틀림이다. 평면 가공, 조립 유격, 프레임 변형, 축 처짐은 이 계산에 포함되지 않는다. 중앙축이 있으므로 지지 헤드를 모두 풀어도 무조건 정밀 자세를 유지한다고 가정하지 않는다. 작업 중 반대 두 헤드 지지를 유지한다.

## 구매/가공과 출력 구분

- `purchase_BOM.csv`: 동력/베어링/축/레일/프레임/스프링 전체 수량.
- `fastener_BOM.csv`: 나사·너트·인서트 규격과 전체 수량. 여분 수량 미포함.
- `purchase_and_cut/`: 패널, 금속 판, 금속 휠, 중앙축 등의 STEP 및 패널/평판 DXF.
- `print/`: 출력용 STL, 같은 부품의 조립좌표 STEP. 출력 수량/크기는 `manufacturing.json`.
- 출력 불가/부적합 대체품: **금속 축·다월핀·베어링·레일·벨트·스프링·인덱스 휠**을 FDM으로 대체하지 않는다.
- 출력물은 PETG를 시작 재료로 권장. 큐브 접촉면은 PLA도 시험 가능. 0.16~0.20 적층, 외벽4~6겹, 코어/허브/브래킷은 높은 충전율을 시작점으로 사용한다. 강도 보증값은 아니다.
- STL 전체가 베드에 닿는 것과 내부 오버행이 없어지는 것은 다르다. 코어·엣지·코너·캐리지는 지지대 제거 접근성과 첫 층을 슬라이서에서 확인한다. 베어링 구멍과 핀 구멍은 시험 출력 후 리밍/치수 보정한다.

## 조립 순서

1. **시험편**: 소켓 Ø3.2/3.4/3.6 및 중앙축 시험편을 출력. 삽입·해제 공차와 D 키 시임을 정한다.
2. **코어**: 중앙축에 내부 링2개를 z=±8~13에 고정. D 키 시임과 분할 코어를 M3×20 4개로 조립. 코어의 X/Y 센터용 인서트4개를 넣는다. 링 세트스크류는 코어를 닫기 전에 조인다.
3. **큐브**: M3 센터4개, F/B 관통 센터2개, 엣지12, 코너8을 조립. F/B는 면 바깥에 스프링(압축길이3), 와셔0.5, ID6/OD≤12/폭5 링을 배치. 손 회전 6면부터 검사한다. 고정축이 있어도 각 면은 90° 회전 가능해야 한다.
4. **헤드1개**: 하우징에 베어링을 넣고 캡 체결, 축/허브/구동판을 조립. 앞 핀 돌출8 중3만 소켓에 삽입. 실리콘 패드가 위치를 잡고 핀 끝은 소켓 바닥과1.2 여유를 둔다.
5. **축 포획**: 뒤 추력 베어링, 직결 헤드의 두께2 시임, 금속 인덱스 휠을 조립. 금속 휠을 조절해 축 이탈을 막고 회전이 뻑뻑해지는 예압은 피한다. 휠 M4 탭2곳에 세트스크류를 넣는다.
6. **잠금 브래킷**: 캐리지 x=24,z=65/75에서 M3×18 두 개로 체결. 직결 핀 Ø3×30은 z=56~86, 중공 핀 Ø3×40은 잠금 z=56~96 /주차 z=64~104. 손잡이 외형은 OD7/높이3 이하. 중공 캐리지의 중앙 Ø42 작업창과 별도 주차 홀을 사용한다.
7. **이송부**: MGN 블록과 캐리지 체결. M5 너트는 뒤쪽 열린 면으로 넣고 돌기가 있는 덮개로 포획. 고정 반력 플랜지195~201 양쪽에 와셔와 더블너트를 넣어 회전은 허용하되 축 이동을 막는다. 손잡이는 잼너트로 고정한다.
8. **프레임**: 하판 → 좌우/뒤판 → 프로파일 → 모듈 순서. 모서리 ±180 위치에 앵글24개. 2060 앞 끝은 z5, 뒤 끝은251.5. 지지대 고정 M5 머리를 이송 너트 경로에 옮기지 않는다.
9. **중앙축 양 끝 고정**: F/B 브리지와 SHF6를 정렬. 한쪽을 고정한 뒤 반대쪽을 힘으로 끌어 맞추지 말고 조립 위치를 맞춘다. 중공축을 0~24 이동시키며 중앙축과 접촉하지 않는지 확인한다.
10. **한 수 시험**: 아래 절차대로 반대 면을 잠근 후 H를 입력한다. 처음부터 긴 섞기/풀이를 실행하지 않는다.

금속 휠과 잠금 브래킷의 **작동 핀 홀은 실제 Ø3 핀에 맞춰 Ø3.05(+0.02/0)를 목표로 리밍**한다. 주차 홀은 Ø3.2로 넉넉하게 둔다. 핀/휠 한 접점 명목 각도 여유는 약0.09°이며 브래킷 홀·축 체결 유격이 더해진다. 시임과 조립을 포함하여 최종 반대 면 각도 변위를 실측한다.

## 한 면 회전 절차 / 펌웨어

예를 들어 F를 회전할 때:

1. F/B를 결합하고, B 잠금핀을 인덱스 휠에 넣는다.
2. F 핀을 주차 홀로 옮긴다. U/R/D/L은24 이상 후퇴한다.
3. 모든 다월핀 정렬과 배선 여유를 눈으로 확인한다.
4. 115200 시리얼에서 `M F`를 입력하면 `PREPARE F: ENGAGE FB; LOCK B; PARK F`가 나온다. **준비를 완료한 뒤 `H` 한 줄**을 입력하면 한 수만 돈다. 다음 수도 다시 확인한다.
5. 축이 바뀌면 기존 지지 쌍을 유지한 채 새 쌍을 먼저 결합한다. 새 반대 면을 잠그고, 작동 면 핀을 주차시킨 후 직교 헤드를 후퇴한다. 홈이 맞지 않으면 강제로 삽입하지 않는다.

`X` 또는180초 확인 시간초과는 중단하며 이미 완료한 수까지의 모델 상태는 보존한다. 잘못된 여러 문자 확인은 실행하지 않는다. `Q 1`은 **모터 신호가 없는 가상 모드**이며, 시뮬레이션 테스트는 명시적으로 이 모드에 들어간다. `Q 0`은 실제 모터/매 수 확인 모드. `S`/`V`도 수동 확인을 거친다. 잠금핀이 들어간 면을 모터로 돌리지 않는다.

풀스텝200/회전, 모든 헤드 전달비1:1로 50스텝=90°. 초기 구동 간격12~8 ms, 정착250 ms. 실제 방향은 면별 저속 시험으로 확인해야 한다. A4988 마이크로스텝을 바꾸면 STEPS_PER_QUARTER도 바꿔야 한다. 탈조·손 회전·전원 중단 후 `SOLVED ok=1`은 실제 상태를 증명하지 않는다. 실제 큐브를 풀린 상태로 맞추고 `R`로 재동기화한다.

**자동화가 완료된 로봇은 아니다.** 현재 실제 제작 가능한 범위는 수동 이송/수동 잠금/한 수 승인 시운전이다. M5 이송은24 이동에30바퀴라 전체 풀이에는 느리다. 완전 자동화를 위해서는 6개 이송 구동기, 결합/후퇴 감지12점, 잠금핀 상태 감지 및 구동, 추가 I/O/전원, 정지 인터록을 설계해야 한다. 단순 지연시간만 넣어 자동 운전으로 바꾸지 않는다.

## 실제 배선

STEP U/R/F/D/L/B =D2..D7, DIR =D8..D13. LCD A4/A5, 버튼 A0/A1, 부저 A2 유지. 드라이버 VDD=5 V, GND 공통, RESET/SLEEP을 함께 5 V로 올린다. 풀스텝으로 MS1/2/3 LOW. VMOT는 독립12 V DC, 드라이버 가까이100 µF/25 V 이상 전해콘덴서6개, 각 모터 전류 제한/VREF 설정, 방열판과 적정 배선. 기존 `diagram.json`은 Wokwi 논리 배선이며 실제 VMOT·퓨즈·전원 배선을 모두 나타낸 도면이 아니다.

12 V 8~10 A는 초기 선정 제안이며 모터 정격과 실제 소비전류/발열을 측정하여 확정한다. UNO 5 V/USB나 브레드보드 접점으로 모터전류를 공급하지 않는다. 모터전원 차단 스위치와 회로에 맞는 퓨즈를 둔다. 전원을 켠 상태에서 모터 커넥터를 탈착하지 않는다.

## 검증 기록과 남은 실물 검증

- `mechanical_checks.json`: 최종 명목 CAD 검사 `passed: true`, 부피 겹침 허용0.02 mm³.
- 3개 축 각각15/30/45/60/75/90°에서 조각 간섭과 중앙축 접촉 검사.
- 직결/중공 헤드 내부, 중요 M5 머리 외형, 잠금/주차 핀 손잡이 간섭 검사.
- 0/12/24 이송과 네 지지 자세(전체 결합, F/B, R/L, U/D), 프레임과 중앙축/키 검사.
- 각 출력 부품 단일 유효 솔리드 및220 베드 외형 검사.
- 출력 STL23종은 모든 에지에 두 삼각형이 연결되는 닫힌 단일 메시, 일관된 면 방향, 양의 부피를 확인했다. OCC 곡면 극점에서 생긴 퇴화 삼각형은0.00001 mm 정밀도 정점 병합과 함께 제거했다. `mesh_checks.json`은 메시 위상 검사이며 서포트/강도 검증은 아니다.
- UNO R3: 27,666 B flash /976 B global RAM. UNO R4 WiFi:77,712 B flash /9,368 B global RAM 컴파일 통과. R4의 LiquidCrystal I2C 라이브러리 아키텍처 경고는 있어 LCD 실물 동작 확인 필요.
- Wokwi 시드1: 20수 섞기→50수 풀이, JS와 각 단계/수열 일치, `SOLVED ok=1`. 가상 모드에서 검사.
- Wokwi 수동 모드: 잘못된 HX 거부, 승인 전 X 취소, H 후 한 수 실행, 두 번째 수 X 취소, 완료 상태 보존, 가상 역수 복구 통과.
- Wokwi 기존 SCRAMBLE/SOLVE 버튼 흐름도 명시적 가상 모드에서 통과했다.
- JS 풀이300개 시드 회귀 통과. 풀이 알고리즘/탐색 순서는 변경하지 않았다.
- 이산 표본만 검사하므로 연속 운동 전체, 큐브 조각 이탈, 인쇄 변형, 실제 나사 내부, 마찰, 강도, 탈조, 센서 상태를 증명하지 않는다. 구매 외형 가정이 바뀌면 검사를 다시 수행한다.
- 실물 합격: 6면 손회전20회, 코어/반대 면0.10 N·m 양방향 하중에서 지속 미끄러짐 없음, 목표 각도 변위<0.5°, 각 면90°/180°/역방향20회 반복 뒤 누적 오차<0.5°, 이송/배선 접촉·과열 없음. 이 값은 **시험 목표**이며 실제 측정 결과가 아니다.

## 재생성

```powershell
python -m pip install -r tools/requirements-robot-v3.txt
python tools/build_robot_v3.py
python tools/check_robot_v3.py
python tools/check_print_meshes_v3.py
python tools/draw_robot_v3.py
powershell -ExecutionPolicy Bypass -File scripts/build.ps1
node tools/gen_manual_v3_test.js
powershell -ExecutionPolicy Bypass -File scripts/simulate.ps1 -Scenario tests/manual_v3.test.yaml -TimeoutMs 90000
```

V3 생성기는 V2의 큐브 유지 트랙/기본 헤드를 재사용하지만 V2 출력물을 덮어쓰지 않는다. 현재 고정 치수로 작성한 생성 스크립트이며 `P`는 주요 값 기록이다. `P`의 숫자만 바꾸면 모든 형상이 자동으로 갱신된다고 가정하지 않는다. 변경할 때 형상 코드와 도면/BOM/검사를 함께 수정한다. `sim/app.js`에도 V3를 반영했으며 바깥 부분은 개방 프레임으로 표시한다. 이 개방 프레임은 표시 변형이므로 실제 제작은 STEP/GLB/PDF 치수를 따른다. 시뮬레이터 갱신 방법은 `docs/SIM_V3.md` 참고.

Fusion에서 `models/robot_v3/robot_assembly.step`을 열면 솔리드를 편집할 수 있다. 생성 피처 타임라인/운동 조인트는 없다. Fusion용 가져오기 스크립트도 제공하지만 실제 가져오기 성공 여부는 별도 기록을 따른다.

```powershell
node tools/fusion-bridge/import-robot-v3.mjs robot
```

이 명령은 기존 MCP 브리지를 사용해 새 Fusion 문서를 만들고 F3D를 저장한다. 현재 채팅에서는 Fusion 실행/가져오기를 검증하지 않았다. STEP/STL 생성과 검증은 Fusion 없이 완료했다.
