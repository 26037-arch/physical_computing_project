# 하드웨어 V4 Rev D — 상단 고정 5면 운전·승강 잠금 막대·개별 끝 센서

2026-10-24 · 상태: **CAD 시제품 + 펌웨어·시뮬레이터 구현, 실물 출력·조립·부하 시험 전**.
V3(고정 중앙축·수동 잠금·매 수 `H` 승인)를 대체한다. 이 문서는 펌웨어(`firmware/main/mechanism.*`), 시뮬레이터(`sim/mechanism.js`, `sim/app.js`), CAD(`tools/build_robot_v4.py`)가 공유하는 **치수·좌표·절차의 기준**이다. 세 곳의 숫자가 다르면 이 문서를 고치고 세 곳을 맞춘다.

## 0. 장치 목록 — 기능과 추가한 이유 (현재 기능을 위한 가장 단순한 구성)

큐브 둘레에 **같은 측면 모듈 4개**(F R B L), 아래에 **D 회전 모듈 1개**(측면 모듈과 같되 축이 비어 있고 모터가 옆으로 비킴)와 그 축 속을 지나는 **잠금 막대 1개**. 위는 비어 있다. 이송 모듈6개는 같은 서보 크랭크를 쓰며4개 신호로 제어한다. 각 모듈의 결합/완전 후퇴 끝을 독립 스위치로 확인한다. 흰색 U를 아래로 두고 논리D인 물리 상단은 고정한다.

**없앤 것과 이유**: 위(U) 헤드 — 위가 열려야 큐브를 넣고 뺄 수 있고, 흰색 U가 아래인 자세를 유지해 아래 D헤드로 논리U를 돌린다. 고정 중앙축·인덱스 휠·잠금핀(V3) — 승강 잠금 막대와 결합 스위치가 대신한다. 승강 벨트·원점 스위치(초안) — 큐브는 손으로 D 핀 위에 올려놓는다. 스텝모터 DIR 핀 5개 — 한 번에 한 모터만 움직이므로 DIR 1개를 공유한다.

## 2. 좌표계와 치수 (CAD = 시뮬레이터)

### 물리 검토 Rev D — 상단 고정 운전 (Rev C 뒤집기 절차보다 우선)

형상·행정·프레임은 Rev C를 유지한다. R/L 헤드가 코어/중앙층을 직접 구동하지
않으므로 마찰에 의존한 자동 뒤집기를 폐지한다. 흰색 U를 아래로 장착한
orient=1을 유지하고 논리 D(물리 상단)를 움직이지 않는 15수로 섞고 푼다.
LOCK은 장착 중 계속 결합하며, F/FLIP과 수동 D 명령은 실행 전에 거부한다.
크로스·OLL/PLL 생성표와 JS/C++ 풀이기를 같은 허용 수 집합으로 갱신한다.
각 모듈의 결합/완전 후퇴 스위치를 분리한다(6×2=12개). 입력은74HC165 두 개로
읽고 D12=DATA, D13=CLOCK, A0=/LOAD를 쓴다. A1은 비워 둔다. 기존 직렬
스위치 배선과 혼용하지 않는다. P13에 후퇴 스위치 장공을 추가하고 P29를
두 스위치용으로 연장한다. 서보 사점 과부하 한계는 물리 검토 문서를 따른다.

### 소프트웨어 공통 계약

Rev C의 주 구동계를 유지하고 P13/P29 스위치 받침을 보완한다. 제어 핀·서보 각도/720 ms 이송·모터 펄스와
초기 미장착 상태·논리/물리 면 매핑은 `config/robot_v4.json` 한 곳에서 관리한다.
`tools/gen_robot_contract.js`는 이 설정과 CAD `parameters.json`으로 C++/JS 계약을
생성한다. 웹 재생 배속은 표시만 바꾸며 실제 보드의 속도 설정을 바꾸지 않는다.
Rev D에서는 뒤집기를 사용하지 않는다. 센서 실패 시 해당
수를 실행하지 않고 완료된 수까지의 큐브 상태를 보존한다. 최신 검증은
`docs/PHYSICS_V4.md`를 따른다. `CONSISTENCY_V4.md`는 Rev C 이력이다.

### 통합 제작 Rev C (이전 Rev A/B보다 우선)

원격 `83ade39`의 측면16×50 띠 판/P30·전용 허브, 6×6 잠금 막대,
6.4 사각 소켓(깊이5), 원뿔 끝 Ø3×16 핀과 Ø7 카운터싱크를 유지한다.
잠금 결합 끝 world y=-22.5, 실제 삽입4/바닥 여유1.0, 가이드6.3/캐리지6.1,
J02는6.2/6.3/6.4, J03 두께9.8이다. D는 기존50×50 P07 한 개를 쓴다.
여기에 Rev B의 공통3점 P14 프로파일 직결, P13 턱/장공/위치 결정 포켓,
P23/P29 뒤쪽 인서트와 짧은 나사를 결합한다. 레일은 z4.5..184.5다.
측면 띠 판은 국소 |x|≤8로 D층 상단(-9.7)과 명목1.7 여유를 둔다.
크랭크/링크/서보축과 행정24/30 mm, 제어 절차는 유지한다.
최종 출력은33종93개, 첫 장 번호63개다. M3 인서트69/M4 인서트14,
F17/F18 수량0, F11 32세트/F25 5세트다. 핀은 90° 원뿔 끝(Ø1,높이1)을
갖는 가공 구매품이며 일반 평끝 핀과 혼용하지 않는다.
U/D 센터의 F03은 M3×10 두 개다. 머리 받침면은 중심에서18.5,
인서트 입구11이므로7.5 mm를 통과한 뒤2.5 mm 물린다. M3×14는 안쪽
막힌 파일럿 끝5.5를 지나므로 사용하지 않는다. 일반 센터는 M3×16을 유지한다.
6 mm 막대의 상대 비틀림 강성은 같은 재질/길이의8 mm 대비(6/8)^4≈0.316이다.
원뿔 입구의 포획 범위는 최종 반복 정밀도나 마찰 상태의 자동 정렬을 보증하지 않는다.
변경별 장단점과 채택 이유는 `docs/BUILD_V4_MERGE_REVIEW.md`를 따른다.

### 조립 단순화 Rev B 이력 (Rev C 변경은 위 절 적용)

Rev A의 큐브·축 배치, 모터/서보 수, 서보 축, 24/30 mm 행정과 링크36은 유지한다.
다음은 조립 기준면과 고정부만 바꾼다. 펌웨어의 행정·서보 각도는 그대로다.

- P14 공통 서보 크래들5개는 2060에 직접 3점 체결한다. 위쪽은
  국소(x,z)=(±20,239), 6T 플랜지에 M5×12 두 개, 아래쪽은(-20,171),
  3T 발+P13 6T를 관통하는 M5×16 한 개다. 모든 나사는 Y 방향이다.
  전산봉20개·간격관20개와 패널의 Ø3.6 구멍20개를 제거한다.
- P14 아래 발의 위치 결정 돌기는 x=-28..-12, y=-51.8..-51,
  z=179..183다. P13에는 폭16.4/높이4.4/깊이1.0 포켓을 둔다.
  위치를 손으로 맞추고 돌기가 들어간 상태에서 3점 체결한다. 돌기는 기준만
  제공하며, 하중은 밀착면과 볼트가 받는다. P25 잠금 서보는 기존 M04 체결 유지.
- P13의 레일 좌우 턱은 안쪽 x=±6.2, 돌출1.5(y=-51..-49.5),
  z10..175이다. 레일 폭12 대비 양쪽0.2, MGN 블록 날개 대비0.5 여유.
  레일 앞끝 z4.5/뒤끝184.5에 맞춰 멈춤 턱을 둔다. 기존 z5..185에서는
  서보 몸체 앞끝184.95와 0.05 겹치므로 레일만0.5 앞당겨0.45 여유를 만든다.
  블록/캐리지/축 위치와 행정은 유지한다. 레일 체결공은 중심
  z15부터25피치7개, 폭3.4/전체길이14의 Z방향 장공으로 바꾼다.
  최초 홀 오프셋10 또는15인 레일은 장공 안에서 맞추며, 그 밖은 구매도면 대조.
- 레일의 M3 체결은2060 중앙 T슬롯(x=0)의 M3 T너트7개/레일로 받는다.
  P13 뒤에 일반 육각너트를 가둬 조립 후 접근할 수 없게 만들지 않는다.
  구매2060은 넓은 면 슬롯 x=-20/0/+20을 모두 갖춰야 한다. 레일을 놓기 전
  중앙 슬롯에 T너트를 배치하고 위에서 체결한다. 나사 길이는 실제 레일의
  카운터보어 받침면~밑면+P13 6T+너트 물림으로 정하며 머리는 레일 안에 둔다.
- P23의 기존 네 X 관통공을 뒤쪽 M4 인서트 OD5.6×L4 자리로 바꾼다.
  M04 뒤에서 M4×12+와셔 네 개로 조립한다(6T 금속판+와셔 약1,
  인서트 유효 물림 약4). P29의 두 공도 M3 OD4.6×L4 인서트로
  바꾸고 M3×12+와셔 두 개를 쓴다. 긴 관통 나사와 반대편 너트를 없앤다.
  인서트 입구는 모두 국소 x=-30, 나사 끝 여유는 실측한다.
  인서트 뒤 나사 끝 도피공은 P23 Ø4.3(막힌 끝 x=-21), P29 Ø3.4(x=-19)다.

## 3. Rev D 운전 절차 (C++/JS 공통)

초기에는 미장착·모든 유닛 후퇴다. LOAD 한 번으로 D 받침을 결합하고,
흰색 U가 아래인 실제 큐브를 놓은 뒤 LOAD로 LOCK·FB를 결합한다.
orient=1을 유지하며 논리 U→물리D, F→B, B→F, R→R, L→L이다.
논리D는 물리 상단이므로 수동 수열에 있으면 실행 전에 전체 거부한다.
풀이기는 크로스15수 IDA*, F2L 매크로, D 없는 OLL/PLL 표를 사용한다.
일반6면으로 섞인 큐브 상태도 처리하되 로봇 자체 섞기는 D를 제외한다.

```
물리 F/B: 새 FB 결합 확인 → D 후퇴 끝 확인 → RL 후퇴 끝 확인 → LOCK 확인 → 회전
물리 R/L: 새 RL 결합 확인 → D 후퇴 끝 확인 → FB 후퇴 끝 확인 → LOCK 확인 → 회전
물리 D: LOCK 확인 → D 결합 확인 → 회전 (측면 쌍은 유지)
```

각 명령 유닛의 두 헤드는 각각 목표 끝 스위치가 닫히고 반대 끝이 열려야 한다.
회전 준비 전후에 전체 끝 상태를 다시 확인한다. 양쪽 중 한 헤드라도 중간 위치이거나
양 끝 동시 눌림이면 회전하지 않는다. 실패한 결합은 서보를 후퇴시키고, 이후 명령에서도
캐시된 상태만 믿지 않고 접점을 읽는다. 실패한 수는 큐브 모델에 적용하지 않는다.
센서 오류 후 복구 동작도 실제 끝 상태를 확인해야 한다.

LOCK은 장착 운전 동안 유지한다. 배출은 D 결합 확인 → LOCK·FB·RL 후퇴 확인 순서다.
`F/FLIP`은 `ERR flip disabled: core not coupled`로 거부하며 저수준 모터 함수도 펄스를 내지 않는다.
가상 모드 Q1에서도 고정 상단 규칙은 같고 구동/접점 대기만 생략한다.

재생성 명령(PowerShell, 저장소 루트):

```powershell
& .\.venv-cad\Scripts\python.exe tools/build_robot_v4.py --stl-tolerance 0.1 --stl-angular 0.3
& .\.venv-cad\Scripts\python.exe tools/check_robot_v4.py
& .\.venv-cad\Scripts\python.exe tools/render_robot_v4.py
node tools/embed_models_v4.js
```

의존성은 `tools/requirements-robot-v4.txt`에 기록했다. 기본 build(0.05 mm / 0.12)도 실행한 뒤, 임베드 용량 제한에 맞춰 위 0.1 mm / 0.3으로 재생성했다. `tools/embed_models_v4.js`는 전체 STL이 6 MB를 넘으면 이 허용오차로 자동 재생성·재검사하고, 그래도 크면 지시된 헤드 부품만 넣는다. 이번 결과는 **29종 전체를 포함**, `sim/models.js` **3,116,222바이트(약 3.12 MB)**이며 헤드 전용 축소는 사용하지 않았다. `app.js` 는 측면 헤드에 `drive_plate_strip`, D 헤드에 `drive_plate_2pin` 을 쓴다. 기존 `tools/embed_models.js`는 변경하지 않았다.
